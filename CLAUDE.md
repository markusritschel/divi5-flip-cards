# CLAUDE.md

Divi 5 plugin that adds a **Flip Card** module: two **Face** child modules (front, back), each holding any Divi modules.
Decisions, milestones and the open verification checklist are in `PLAN.md`. Read it first.

## Layout

- `divi5-flip-cards.php`: bootstrap: constants, PSR-4 autoloader (`D5FC\Modules\` → `modules/`), asset enqueueing, Divi-missing notice.
- `modules/`: PHP, front-end rendering. `Modules.php` registers the modules on `divi_module_library_modules_dependency_tree` (skipped, with an admin warning, when `d5fc_missing_requirements()` finds a Divi class or the build output missing).
  - `StarterLayouts/`: the ready-made cards (`layouts/<slug>.html`, Divi block markup) and the code that creates them once as module-type Divi Library items.
- `src/components/<module>/`: Visual Builder side (TypeScript/React) plus the `module.json` definition and styles.
  - `module.json`: the single source of the module definition; copied to `build/modules-json/` and read by PHP.
  - `module.scss`: front end + builder. `style.scss`: builder only (`build/vb-bundle.css`).
- `src/frontend/`: the small front-end script (`build/frontend.js`, not loaded in the builder): flips cards on click, tap and the flip button, turns them back (second click, Escape, pointer leaving), and plays the flip hint.
- `build/`: generated by webpack; not committed. The PHP needs it at runtime.

Every PHP method in `modules/*/*.php` mirrors a TS file in `src/components/*` (named in its doc comment).
**Change both sides together**: classnames, styles, rendering.

## Conventions

- Prefix everything `d5fc`: module names `d5fc/...`, CSS classes `d5fc_...` (BEM-ish: `d5fc_flip_card__inner`, `d5fc_flip_card--left`), PHP namespace `D5FC\`, text domain `divi5-flip-cards`.
- Custom settings follow Divi core's pattern: an attribute (e.g. `flip`) with `settings.advanced.<field>`, read at `attrs.flip.advanced.<field>.desktop.value`.
- Flip behaviour is CSS-driven: per-direction and per-effect CSS custom properties on the card, faces stacked in one grid cell. Hover is pure CSS; the front-end script only sets `d5fc_flip_card--flipped` (click, tap, flip button).
- Builder-only classes (added in the JS classnames or by `edit.tsx`, never in PHP): `--builder` (no hover flipping), `--preview-both` / `--preview-back` ("Show in Builder"), `--play` (one-off preview of the transition).
- Divi 5.15 builder internals used on purpose: `ModuleAdd` (the "+" in empty faces), `moduleUtils.elementsCallbacks` (face Elements list), `divi/edit-post` → `editModuleAttribute` / `getModule` and `divi/modal-library` → `getActiveModals` (Front/Back switch, showing the edited module's face). Re-check them after Divi updates; the e2e suite covers each.
- Registration callbacks (`index.ts`): `callbacks.content['d5fc/flip-card-face'].maxItemsCallback` caps the faces at two; `callbacks.content.<group>.fields.<key>.visible` hides fields, where `<key>` is the attribute path camel-cased per segment with the rest lower-cased (`flip.advanced.backClick` → `flipAdvancedBackclick`).
- Divi toggles store `"on"`/`"off"`. A face's "Text Color" value `"dark"` means a dark background, so light text.
- Default face styles use `:where()` so Divi's design settings always win.
- Code is adapted from Elegant Themes' examples: <https://github.com/elegantthemes/d5-extension-example-modules> (extension structure, parent/child) and <https://github.com/elegantthemes/d5-example-core-modules> (core module sources, e.g. Accordion Item, which holds any modules).

## Commands

```bash
npm install
npm run build       # production build into build/
npm start           # watch mode
npm run typecheck   # tsc; ignores errors inside node_modules/@divi (that package ships broken sources)
npm run lint:php    # php -l on all PHP files
npm run zip         # build + dist/divi5-flip-cards-<version>.zip
```

CI (`.github/workflows/build.yml`) runs typecheck, PHP lint and the ZIP build, and uploads the ZIP as an artifact.

## Testing

The real check is the Visual Builder and the front end in WordPress with Divi 5.15 (LocalWP; see `docs/local-development.md`).

`e2e/` drives both with Playwright against a Docker WordPress (port 8087) that mounts this repo read-only; Divi is unpacked outside the repo. Not in CI (Divi is licensed). Run it before updating Divi on a live site:

```bash
npm run build
e2e/setup.sh /path/to/Divi.zip                 # once; again to reset the fixture pages
cd e2e && pnpm install && pnpm test             # CHROMIUM_PATH=/usr/bin/chromium for a system browser
```

Fixture pages are `e2e/fixtures/<slug>.html` (Divi block markup; every block needs `"builderVersion"`, or Divi's Flexbox migration renders it as legacy block layout). Divi's own "+" buttons ignore clicks in a headless browser, so tests dispatch the mousedown instead.
When Divi is installed locally, its source is at `../../themes/Divi/`; look there for how core modules do things before guessing at the API.
Never commit Divi itself or any ZIP (`*.zip` is git-ignored); it is proprietary.
